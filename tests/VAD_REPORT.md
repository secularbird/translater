# VAD 断句与完整句翻译验收

日期：2026-09-27。

## 行为

- 三种语音模式统一使用官方 sherpa-onnx 1.12.15 中的 Silero VAD，模型和运行时随应用打包。
- 16 kHz 连续重采样，512 样本 VAD 帧；最短语音 0.2 秒，结束静音默认 0.8 秒，可配置。
- 移除普通固定秒数强切。约 25 秒仅为 ASR 保护窗口，`final:false` 且保持发言 ID；识别文本合并，等真实结束或显式停止后翻译。
- 完成的识别文本按句末标点逐句提交，处理英文缩写、首字母、小数及引号；无标点短发言由端点收尾。
- VAD 为声学端点检测，不是语法完整性模型。用户在句中长停顿仍可能形成一个发言端点。
- 保护切点之后额外允许 0.3 秒检测启动余量；收尾失败标记不完整文本，禁止拿半句直接重试翻译。
- 原文、译文仍各一个固定区域，停录后继续追加；ASR/翻译双模型保持常驻。VAD Worker 按录音会话初始化、结束后释放。

## 真实 Silero 边界测试

`npm run test:vad`，见 `test-results/automation/vad-real.json`：

| 输入 | 输出 |
|---|---|
| 3 秒静音 | 无发言 |
| 440 Hz 音调 | 无发言 |
| 单次真实语音 | 一个 final，5.256 秒 |
| 两次语音，中间 0.3 秒静音 | 同一个 final，10.984 秒；不按旧时间上限切开 |
| 连续重复长语音 | 25.256 秒 non-final + 6.888 秒 final，均为 ID 0 |
| 用户显式停止 | 一个 final，5.288 秒 |

短停顿输入使用真实 VAD 裁出的语音，避免用振幅裁剪把呼吸声误算为语音。长窗口结果略超过 25 秒，因为检测确认和帧边界存在余量。

## 真模型验证

### Chromium 完整麦克风链路

`npm run test:offline`：本地模型缓存重载、中英识别、双向翻译和麦克风 → Silero → SenseVoice → M2M100 全部通过，阻断外部请求，记录到的外部请求数为 **0**。

- 识别：`The tribal chieftain called for the boy and presented him with 50 pieces of gold.`
- 译文：`部落领袖打电话给男孩,并向他介绍了50块黄金。`
- 此次从点击开始到停录、队列完成约 12.314 秒，包含播放语音和模型准备，不是纯推理耗时。

译文中“向他介绍了”不是高质量对应，保留原始结果，不将功能链路通过当作准确率验收。

### Android / macOS 打包运行时

两端均使用实际 WebView 加载安装包内 VAD Worker，将真实中文 WAV 经 Silero 输出后送入实际 SenseVoice；文本翻译另外使用 M2M100。

- VAD 输出单一完整发言 4.36 秒。
- 两端识别为 `派饭时间早上9点至下午5点。`；与原句开头“开放时间”有识别差异。该检查确认语言、非空内容及时间信息，不代表逐字正确；端点上下文与模型误识别影响尚未单独归因。
- macOS `tauri://localhost`：VAD、识别、英译中通过。
- Android 17 ARM64 / 16 KB 页：模型静态镜像关闭后 VAD、识别、英译中与两次文字连续追加通过。
- 原生检查注入 WAV 到生产 VAD Worker；浏览器检查则通过测试麦克风走完整应用队列。未将注入音频测试描述为实体麦克风质量验证。

## 模型常驻与启动耗时

最新 APK 两次实际开始/停止录音后显示 `识别 1 / 翻译 1`，停止后显示“双模型已常驻”。

- 本轮首次采样：81.661 秒首次进入录音、5.747 秒再次进入。
- 最终 APK 复测：54.001 秒首次、5.927 秒再次。
- VAD 每个录音会话会初始化；本轮启动明显慢于 VAD 接入前的 7.10 / 0.19 秒。
- 宿主机存在其他大内存进程，但没有隔离负载，不能将变慢全部归因于资源争用或 VAD。性能定位和 VAD 初始化复用仍是后续改进项。

上述计时记录在 `test-results/automation/residency-android-ui.json`，不能套用旧性能基准作为新版结果。
